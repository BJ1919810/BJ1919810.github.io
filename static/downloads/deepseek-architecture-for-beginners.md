## 0. 一句话总纲

大模型每说一个字，都要回头翻一遍自己「读过的一切」。所以它的成本只有两块：

1. **算**：把数字相乘相加（矩阵乘）；
2. **搬**：把「读过的一切」搬进显卡的显存里。

短文本时瓶颈在「算」；**一旦上下文变得很长（十万、百万字），瓶颈就变成「搬」**——显存装不下、带宽搬不动。
DeepSeek 这两年干的事，本质上只有一句话：

> **书越读越厚的时候，别把整屋子的书都搬到桌上，而是边读边做摘要卡。**

---

## 1. 最基础的一层：注意力 = 每次说话前翻自己写过的笔记

模型生成文字是一格一格往外蹦的。每蹦一格，它都要「看一眼前面所有内容」。

如果每一格都把前面所有内容重新算一遍，那就太蠢了。于是有个东西叫 **KV cache（可以理解成笔记本）**：
每读进一个字，就顺手在这个字的旁边写一张小卡片（能查询的「索引」），下次要用直接翻卡片，不重新算。

麻烦在于：**笔记本会越来越厚**。粗略说，一个 token 在每一层要占几 KB。层数一乘、长度一乘，一百万字的上下文就是天文数字——显存放不下，就得往内存、SSD 上倒，一倒就慢。

所以关键问题变成：

> **能不能不存「原文卡片」，只存「这一段的摘要卡」？**

这正是 DeepSeek V4/V4.1 的整条主线。下面逐件拆。

## 2. 三条主线（一张图记住）

| 序列轴 | 历史怎么表示 | CSA / HCA：把 4 个或 128 个 token 压成 1 张摘要卡，再挑着读 | 读书做摘要 |

## 3. 逐件讲清楚

### 3.1 CSA：把每 4 个字合成 1 张摘要卡，再检索着读

- **像什么**：读一本书，不许你回头逐字重读，只许你看自己写的**摘要卡**。每 4 个字写 1 张。
- **怎么做**：不是简单取平均。每张卡对每个「通道」单独学一套权重（哪个字更重要），而且**卡是重叠的**——第 i 张卡同时看第 i 块和第 i−1 块，等于「带上下文地记笔记」。
- **怎么读**：有一个小小的**图书管理员**（论文叫 Lightning Indexer，闪电索引器），拿你当前这句话去给所有摘要卡打分，只挑**分最高的 top-k 张**（Flash 挑 512 张）递给你。
- **省了什么**：卡片数量变成原来的 1/4；再叠加「卡片只存 576 字节」的低精度，一层一个 token 从约 4096 字节降到约 144 字节。
- **代价**：摘要必然丢细节；而且那个图书管理员要**把每句话和所有卡都对一遍**，所以它自己仍是平方级的开销（只是常数小了）。
- **真身**：
  - 压缩：每块学两套候选内容 `C^a/C^b` 与两套权重 logits `Z^a/Z^b`，当前块与前一块各加一个**可学习位置偏置**；每个输出通道在合计 **2m 个位置**上单独 softmax 再聚合（m=4 ⇒ 一张摘要吃相邻两块的 8 个 token），首块前驱用 −∞ logits / 0 内容。**不是「拼接 m 个 token 过一个 Linear」**——那是过度简化。
  - 索引器：`score(t,s) = Σ_h w_{t,h} · ReLU(q_{t,h} · K^I_s)`，只对**已完成**条目打分（`s < floor(t/m)`）再取 top-k=512；64 个索引头 × 128 维，压缩索引 key 被所有头共享。
  - 读取：**K=V 用同一个压缩向量**（V4 的关键简化），并且和最近 128 token 的原文**拼进同一个** core attention；512 维里**只对最后 64 维施加 RoPE**（partial），因为同一向量兼作 value，输出要**逆旋转**；每头一个只有 logit、没有 value 的 **sink**（所以内容注意力质量可以 <1）。
  - 代码：`csa.py:206` `_compress`｜`csa.py:213-219` `_indexer_scores`｜`csa.py:102` `sparse_attention`｜`csa.py:86` `_entry_visible`｜`csa.py:93` `_topk_visible`｜`csa.py:37` `apply_rope`。判据 `tests_csa.py`。
  - 已知缺口：索引器的**辅助损失**在 `csa.py:291` 算得出来（`indexer_kl`），但 `model.py` 的 `forward` 目前**只用了 MoE 的平衡损失**，没把它加进总损失 ⇒ `idx_*` 参数拿不到梯度（`tests_optim.py` 那条「每个可训练参数都要有非零梯度」的红就是它）。**待裁决**。

### 3.2 HCA：每 128 个字合成 1 张粗卡，不挑，全看

- **像什么**：不是摘要卡，是**每章的目录条目**。128 个字压成 1 条，条目少到可以**全部看一遍**，不需要管理员挑。
- **好处**：不会有「该看的卡没被挑中」这种漏检。
- **代价**：条目更粗，细节更少。
- **为什么和 CSA 交替用**：一个细但可能漏，一个粗但不会漏，轮着来互补。
- **真身**：128:1 **非重叠**、块内 softmax + 可学习块内位置偏置，**没有 selector**；候选数 ≈ floor(t/128)（1M 尾端约 8192 条）。
- **我们这版没实现**：复刻跟的是 **V4.1 骨架**，而 V4.1 是**纯 CSA2、取消了 HCA**（CSA/HCA 交替是 V4 的事）。所以这一节讲的是 V4；代码里没有对应文件。

### 3.3 局部窗口（SWA）：最近 128 个字的**原文**不许丢

摘要卡再香，也有个致命问题：**你正在读的这一段还没写完，摘要不了**；而且最近几行的细节往往最关键。
所以每层都额外保留**最近 128 个 token 的原文**，和挑出来的摘要卡拼在一起读。这段原文的存储量与总长度无关（永远是 128），这也是为什么它不会拖累长上下文。
- **真身**：窗口 128 的**未压缩** KV，关键是它**拼进同一个 core attention**（不是另开一条 q/o 分支）。代码：`csa.py:81` `_swa_mask`，拼接在 `csa.py:222` `CSALayer.forward`。

### 3.4 层维复用（V4.1 的 CSA2 三模式）：同一张卡，几层共用

V4.1 又往前走了一步：一组 5 层里，只有**第 1 层**负责算卡片、算索引；后面 4 层直接**复用**它的卡、它的索引，甚至**连「挑了哪 k 张」都照抄**。三种模式分别叫：

- **Full**：自己算卡 + 自己做索引；
- **Reindex**：复用卡，但用自己的问题重新挑一遍；
- **Reuse**：卡和「挑好的结果」全部照抄。

这一招的收益是纯赚：后面几层**连参数都不需要**（不存 KV 投影、不存索引器），显存和算力一起省。
- **真身**：`group=5`，模式表由 `csa_modes()` 生成——**编码器**每组 = 1 Full + 4 Reuse；**解码器**首组 = 1 Full + 4 Reuse，之后每组 = 1 Reindex + 4 Reuse。Reuse 连「挑了哪 k 张」都照抄。代码：`model.py:31-45`，三种模式在 `csa.py:222` 里分支。

### 3.5 MoE：不是所有专家都上班

- **像什么**：医院有 256 个专科医生（这是 V4-Flash 的编制，Pro 版是 384 个），你每次看病**只挂 6 个号**，另外还有 1 个「全科医生」永远在场。
- **怎么做**：一个门卫（路由器）按当前的词决定叫哪几位专家。老办法要给门卫加「平衡罚款」，DeepSeek 用了一个更巧的：**给每个专家挂一个偏置分，只影响「叫不叫你」，不影响「你说话算多少分量」**——你可以把它想成门卫手边的一张小纸条：谁最近号挂得太多，就把谁往后挪一格；谁一直闲坐着，就往前挪一格。挪来挪去，动的只是「排不排得到你」，不动专家说话的分量，所以既不塌房（都挤到一个专家），也几乎不用罚钱。
  > 严谨半句：「不靠罚款来均衡」不等于「一分钱都不罚」——报告那边还留了一笔很小很小的兜底罚款（一个 1e-4 量级的序列级平衡损失），平时基本不吭声，只当安全绳用；天天干活的是那张小纸条。（这条按我们整理的报告口径。）
- **省了什么**：参数量可以极大（284B），但每个 token 实际参与运算的只有 13B ⇒ 算力按激活量付钱。
- **代价**：专家分散在多张卡上，通信变贵；DeepSeek 为此专门写了融合大核（MegaMoE/DeepGEMM）。
- **真身**：
  - 亲和度 `s = sqrt(softplus(x·W_r))`（**不是 softmax**，也没有固定上界）；选择分数 `score = s + b_i`，但**混合权重用没加 bias 的 s 再归一化**——报告原式 `g_{i,t} = ρ · a_{i,t} / Σ_{j∈S_t} a_{j,t}`，`ρ = 1.5`(Flash) / `2.5`(Pro)。
  - 均衡：`b_i -= γ · sign(load_i − 1/n)`——**符号写反就是正反馈塌陷**（过载的专家越加越重）；另有权重 **1e-4** 的序列级平衡损失兜底。
  - 组限制（可选）：组得分＝组内 **top-2 之和**，只在得分最高的组里挑专家。
  - 代码：`moe.py:64` 亲和度｜`moe.py:69`+`:77`（bias 只进选择、权重用原始亲和度）｜`moe.py:72` 组得分｜`moe.py:105-107` 兜底损失｜`moe.py:112-124` bias 方向（docstring 明写反向即正反馈）。判据 `tests_moe.py` 34 条断言，含**冻结 bias 的负向对照**：修前给 6 个饿死专家的流量 `0.0000`（与冻结对照无区别），修后 `0.3650`。
  - **我们与报告的差异（别当官方口径）**：报告（V4）**前 3 个 MoE 层用 hash routing**，我们只做「第 0 层 dense」；报告**取消了 node-limited routing**；规模差很远（报告 256 专家/top-6，我们 16/top-2）。

### 3.6 mHC：把「一条残差线」变成「四条草稿线」

- **像什么**：原文只用一条草稿线记录「前面写了什么」。mHC 用**四条**，每层学一个「怎么在四条线之间倒腾」的小矩阵。
- **关键约束**：倒腾矩阵被强行限制成**双随机矩阵**（每行每列加起来都等于 1）。这样的矩阵**不会把数值越放越大**——这是给深层网络防爆的保险丝。
- **代价**：论文自己承认，实际部署要专门写融合算子，否则多出来的读写会拖慢 6.7%。
- **真身**：`X_{l+1} = B_l X_l + C_l F_l(A_l X_l)`，残差流从 1 条扩成 **n=4 条**；`A = Sigmoid(Ã)`、`C = 2·Sigmoid(C̃)`，`B` 用 **20 轮 Sinkhorn–Knopp** 投影到 **Birkhoff 多胞形**（非负且行列和都为 1 ⇒ 谱范数 ≤1、乘积仍双随机）。额外宽度**只在残差状态**，attention/MoE 的输入输出仍是 d，所以参数开销小，但**激活与跨流水线通信变贵**。
- **我们这版没实现**：mHC 不在 P0 里；代码里 `mhc` / `Birkhoff` / `Sinkhorn` 一个函数都没有（`optim.py:10` 只有一句「待做」注释）。

### 3.7 Muon：每次只修正「方向」

- **像什么**：普通优化器（AdamW）像一个**逐格调整**的修音师；Muon 更像**先把整段旋律摆正方向**再动手。
- **怎么做**：把梯度矩阵做一次「正交化」（近似只保留方向，抹平尺度差异），乘一个固定系数（0.18）再更新。数值上表现为：**每次更新的幅度是稳定可预测的**。
- **配比**：矩阵权重用 Muon；embedding、输出头、各种归一化层用 AdamW。
- **代价**：Muon 必须看到**完整的一个矩阵**才能正交化，所以不能像 AdamW 那样把一个矩阵随便切到多张卡上——这逼着他们重写并行系统。
- **真身**：梯度 → 动量+Nesterov → 按 Frobenius 范数归一化 → **8 轮快 + 2 轮稳**的 hybrid Newton–Schulz（前 8 轮系数 `3.4445 / −4.7750 / 2.0315` 把奇异值快速推向 1，后 2 轮 `2 / −1.5 / 0.5` 让 1 成为稳定不动点）→ 更新乘 `sqrt(max(n,m)) · γ`，`γ = 0.18`（对应目标 update RMS）→ decoupled weight decay。
- 代码：`optim.py:17-30` Newton–Schulz｜`optim.py:33` Muon（`gamma=0.18, fast=8, stable=2`）｜`optim.py:95` `split_params` 按角色分派。判据 `tests_optim.py`，带负向对照：**原始梯度的 RMS 必须「不是」0.18**（否则等于没做正交化）。
- **分派口径**：报告说 embedding / 输出头 / mHC 静态 bias 与 gating / 全部 RMSNorm 用 AdamW，其余矩阵用 Muon；`optim.py:95` 的 `split_params` 就是按**名字**排除 `embed` / `lm_head`（norms 是 1D 也进 AdamW，tied 权重只计一次）。
- **一条「假 bug」值得记**：`tests_optim.py` 那条「embeddings/head go to AdamW」曾长期报红。回码核对后发现 `split_params` 本来就是按名字分派的——是**断言自己写错了**：它要求「AdamW 里所有带 `weight` 的张量都必须是 embed/head」，而下一行又要求 norm（也是 1D `.weight`）在 AdamW 里，两条自相矛盾。2026-10-19 改的是断言，不是代码。
- **真正缺的那块（已修）**：索引器的监督信号原先只算不用 —— `csa.py:291` 算出 `indexer_kl`，但 `model.py` 的 `forward` 只把 MoE 的平衡损失加进总损失。后果是 `idx_*` **零梯度**、top-k 等于随机挑卡。现在 `forward` 加上了 `loss_indexer = w · aux`（`w = 1e-3`），`tests_optim.py` 的「每个可训练参数都要有非零梯度」由红转绿。
- **Sinkhorn 平衡更新**（V4.1 用在 embedding/头上）：**未实现**，`optim.py:10` 注明是「排队做 A/B，不靠猜」。

### 3.8 Engram：条件反射式的「背记」

有些东西不值得「推理」，直接查表更快：比如常见词组。Engram 就是**用哈希把 n-gram 映射到一张巨大的记忆表**（V4.1 里有 196B 参数），再加个门控决定这次要不要用。像人的条件反射。

- **真身**：哈希 n-gram → 巨型记忆表 + 门控。**我们没实现**（196B 跟 8GB 卡没关系，但把它列进来是为了说明「这份稿讲的是真机，不是我们的复刻」）。

### 3.9 DSpark + FP4：一个管「抢答」，一个管「速记」

- **DSpark（投机解码）**：先让一个小模块**抢答**几个词，再让大模型一次校验。答对了就等于一步走好几格。（V4.1 为此**取消了 MTP** 那个辅助预测头。）
- **FP4/FP8（低精度）**：把卡片上的数字用更少的位存（速记符号）。注意：**低精度主要是省「存储和搬运」，不是省「计算」**——DeepSeek 的做法是存的时候压扁，**真正做注意力前先还原**。
- **真身**：DSpark＝投机解码（小模块抢答几个词，大模型一次校验，答对就一步走好几格）；FP4 是 **MXFP4 + QAT**，在 **RoPE 之后量化、注意力之前反量化**，所以省的是**存储与搬运**。
- **我们没实现**：MTP 按 V4.1 取消；SM86（3070）没有 FP8/FP4 张量核——V4 那个「FP4 indexer」在我们这儿只能停在纸面。

## 4. 到底省了多少（算一笔账）

第三方分析页给的口径：

| 项 | 每 token 每层占多少 |
|---|---|
| 传统做法（BF16、GQA8、head dim 128） | 约 **4096 字节** |
| 一个 DeepSeek 压缩条目（64 维 BF16 + 448 维 FP8） | 约 **576 字节** |
| CSA 层（4:1 压缩） | 576 ÷ 4 = **144 字节** |
| HCA 层（128:1 压缩） | 576 ÷ 128 = **4.5 字节** |
| 两类层各半 | 约 **1.8%** |

也就是说，**长上下文最贵的那部分开销，降了约两个数量级**。这才是「一百万 token 上下文能真跑起来」的物质基础。

## 5. 天底下没有免费午餐

- **压了就丢**：报告自己给的数据——128K 以内检索还稳，**256K 之后明显掉**；Pro 版在 1M 时从 0.92 掉到 0.59。
- **索引器不免费**：CSA 的图书管理员仍是平方级开销（约 N²/(2m)），只是常数被压缩、精度被降到 FP4 而已。
- **复杂度爆炸**：作者自己承认组件太多、有些技巧（Anticipatory Routing、SwiGLU clamp）**机理至今没完全搞懂**。
- **账单不透明**：训练用了多少卡、多少天、多少钱，报告**一个都没给**。

## 6. 所以我们为什么要自己复刻一个小号

我们不是要复现能力（那是 32T～45T token、几千张卡的事），而是**验证机制**：

- **能复刻**：CED（解码器的 KV 由编码器投影）、CSA2 三模式跨层复用、MoE 的无辅助损失均衡、Muon/Sinkhorn 优化器；
- **不能复刻**：45T token、FP8 训练内核、256 / 384 个专家（Flash / Pro）、196B Engram；
- **能得到的结论**：这些机制在**小规模下能否稳定训练**、以及**关掉它们时指标是否真的变差**（这才是「理论是否真在起作用」的证据）。

## 7. 名词小抄

| 名词 | 一句话 |
|---|---|
| KV cache | 把读过的内容的「查询卡」存下来，避免重复计算 |
| CSA / CSA2 | 每 4 个字压成 1 张重叠摘要卡，再挑 top-k 读 |
| HCA | 每 128 个字压成 1 条粗条目，全读不挑 |
| SWA（滑窗） | 最近 128 个字的原文永远留着 |
| Indexer（索引器） | 决定「读哪几张摘要卡」的小评分员 |
| Full / Reindex / Reuse | 自己算卡 / 复用卡但重挑 / 卡和挑选结果全照抄 |
| MoE | 很多专家，每个 token 只叫几个 |
| mHC | 四条残差草稿线，混合矩阵受双随机约束防爆 |
| Muon | 把梯度正交化后再更新的优化器 |
| Engram | 用哈希查表实现的「条件反射式」记忆 |
| MTP / DSpark | 多预测一个词（V4）/ 抢答再校验（V4.1 取代 MTP） |
| FP8 / FP4 | 低精度存储，省显存带宽；算前还原 |
